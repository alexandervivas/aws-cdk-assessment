# Architecture decisions

This is the design at a glance, and it is kept current. Every change to a decision updates this table, its ADR and [`docs/plan.md` §13](plan.md) in the same pull request. The brief's original decisions are 1–8. Rows marked **(added)** or **(refines N)** were decided with the owner during delivery. A row also marked **proposed** waits for the owner's approval, as its ADR does. The one-line index is [docs/adr/README.md](adr/README.md).

| # | Decision | Why | Rejected alternative | ADR |
|---|----------|-----|----------------------|-----|
| 1 | Derive `PersonCreated` from the DynamoDB stream through an EventBridge Pipe (outbox through change data capture) | The table write is the only write. Every committed insert produces an event at least once, except in the first-deploy window before the pipe runs. A record that fails for 6 h is dead-lettered and needs the manual recovery in the operations notes, and the Lambda has no publishing code. | Lambda writes the person, then calls `PutEvents`: a partial failure leaves a person without an event | [0001](adr/0001-outbox-via-streams-and-pipes.md) |
| 2 | Thin event: `personId` and metadata, no PII | Personal data never leaves the service, GDPR erasure stays possible, and consumers decide what they need | Fat event carrying the whole person | [0002](adr/0002-thin-event.md) |
| 3 | Synchronous `201 Created` | The client gets the id and validation errors immediately | API → SQS → Lambda with `202` | [0003](adr/0003-synchronous-created.md) |
| 4 | Idempotency through an `Idempotency-Key` header and one DynamoDB transaction (person and key) | Retries are safe, and a duplicate never reaches the stream, so it never produces a duplicate event | Powertools idempotency (needs AspectJ); payload hashing as the key | [0004](adr/0004-idempotency-key-and-transaction.md) |
| 5 | REST API (v1). API Gateway validates the body against the schema. The handler alone enforces `Idempotency-Key`, case-insensitively | JSON Schema request validation, IAM auth, per-stage throttling | HTTP API (no body validation) | [0005](adr/0005-rest-api.md) |
| 6 | IAM (SigV4) authentication | Service-to-service, no secrets to manage | API keys; Cognito | [0006](adr/0006-iam-authentication.md) |
| 7 | One CDK Stage per environment; every difference lives in `EnvironmentConfig`. The API name and the Powertools service name are stage-specific (`person-service-{stage}`) | Same template for every environment, no name collisions, and metrics never mix when Dev and Prod share an account | Copy-pasted stacks per environment | [0007](adr/0007-one-stage-per-environment.md) |
| 8 | Java 25 with SnapStart, behind a `live` alias | The requested language; SnapStart removes most of the JVM cold start | Node/TypeScript Lambda | [0008](adr/0008-java-and-snapstart.md) |
| 9 | **(refines 4)** Idempotency keys are scoped per caller, using the IAM principal with the STS session stripped | Two callers sharing a key must not get each other's 422 or person id | Global keys; full-session scope (breaks retries from a new session) | [0009](adr/0009-per-caller-idempotency-scope.md) |
| 10 | **(refines 4)** Request fingerprint: SHA-256 over a canonical form, behind a port | No per-request cost or extra dependency. Swapping in an HMAC later changes one class | KMS HMAC per request: cost, latency and a new failure point (on the roadmap) | [0010](adr/0010-request-fingerprint.md) |
| 11 | **(refines 4)** Write semantics: cancellations branch on reason codes, transient ones back off over 3 attempts, the key window is a fixed 24 h, and `ClientRequestToken` is the candidate id | No spurious 500s under bursts, a deterministic expiry, and a lost-response retry that still reports a fresh create | Retry once without backoff; treating any stored key as valid forever | [0011](adr/0011-idempotent-write-semantics.md) |
| 12 | **(added)** `415` for non-JSON bodies | API Gateway skips body validation for content types that have no mapped model | `400 malformed`; relying on API Gateway alone | [0012](adr/0012-unsupported-media-type.md) |
| 13 | **(added)** Exactly three unavoidable IAM wildcards (X-Ray writes, the log-group stream suffix, KMS prefix actions on the stage key), enforced by a test | Tracing and CMK encryption require them. Any other wildcard fails the build | Managed policies that hide the same `*`; turning tracing off | [0013](adr/0013-iam-wildcard-exceptions.md) |
| 14 | **(added)** The stack sets the account-level API Gateway logging role and retains it. This is accepted for the assessment, so deploy into a dedicated account | Access logging needs it, and a fresh account would otherwise fail to deploy | An account prerequisite (manual step); disabling access logs | [0014](adr/0014-account-level-apigateway-logging-role.md) |
| 15 | **(added, proposed)** cdk-nag `AwsSolutionsChecks` fails synthesis on any finding not acknowledged where it arises, with a reason citing an ADR. No WAF and no API Gateway execution logging | IAM already rejects unsigned traffic, and execution logs can quote request values that a log data protection policy can't reach | Stack-wide suppressions; a WAF web ACL; execution logs at `ERROR` | [0015](adr/0015-cdk-nag-acknowledged-findings.md) |
